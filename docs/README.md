# OctoAcme Project Management Docs

OctoAcme uses a customer-first, iterative project process with clear ownership and data-informed decisions. Projects move from initiation (validate the need, stakeholders, and success measures) through planning (agree scope, backlog, dependencies, milestones, and Definition of Done), execution (deliver and track small increments), release (deploy and verify), and retrospective improvement.

## How the process works

- **Workflows:** Teams use a project board to track work from backlog through review, QA, and completion; small pull requests link to issues and acceptance criteria. Demos, risk reviews, release checks, and retrospectives keep delivery visible and lessons actionable.
- **Roles:** The Project Manager coordinates schedules, risks, and communication; the Product Manager defines outcomes and prioritizes work; Developers build and test; QA/Testing validates quality and acceptance criteria; stakeholders provide input and approvals.
- **Communication:** Teams agree on delivery-team standup cadence, hold regular PM/Product Manager and delivery syncs, share monthly or milestone-based stakeholder updates, and escalate blockers from the team through the PM and Product Lead to the sponsor as needed.
- **Quality assurance:** Work is checked against acceptance criteria and the Definition of Done, with unit and applicable integration tests, CI linting and tests, security scans, and manual QA when needed. Releases include smoke tests, rollback planning, and post-deployment verification.
